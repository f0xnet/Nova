Démarrer avec Nova Script

Tout ce qu'il faut savoir pour écrire votre premier script de jeu.

C'est quoi un script ?

Un script est un fichier .lua attaché à une entité (joueur, ennemi, objet…). Il définit le comportement de cette entité : que fait-elle à chaque frame ? Comment réagit-elle aux coups ? Aux touches du joueur ?

Aucun require() nécessaire. Tous les modules Nova (Timer, World, Sound, etc.) sont disponibles partout, directement, comme des variables globales.

Fonctions principales du cycle de vie

Les deux fonctions fondamentales d'un script d'entité — définissez-les en minuscules :

FonctionQuand est-elle appelée ?
init(entity)Une seule fois au chargement. Les propriétés JSON de la scène sont accessibles via self.
update(entity, dt)Chaque frame. dt = secondes depuis la frame précédente.
entity est un global. La variable entity est injectée dans l'environnement du script et accessible depuis toutes les fonctions (init, update, OnMessage, OnKeyDown…) sans avoir à la passer ou la sauvegarder manuellement.
Propriétés JSON → self. Les propriétés définies dans le JSON de scène ("properties": { "vie": 50 }) sont disponibles dans self.vie, self.vitesse, etc.

Named handlers (handlers nommés)

Ces fonctions sont branchées automatiquement sur les événements correspondants. Définissez celles dont vous avez besoin — elles seront appelées sans EventBus.on() manuel.

Nettoyage automatique des handlers. Quand une entité est détruite (Registry.destroyEntity), le moteur émet entity_destroyed avant la suppression, ce qui déclenche automatiquement : désinscription de tous ses named handlers et de tous les EventBus.on() appelés dans init(entity), suppression de son environnement Lua, et nettoyage de Stats / Effect / Cooldown / Anim. Aucune gestion manuelle n'est nécessaire.
Scripts de scène : named handlers et EventBus.on() nettoyés automatiquement. Au changement de scène, tous les named handlers (OnKeyDown, OnMessage…) et tous les EventBus.on() appelés dans init() du script de scène sont retirés automatiquement. Pour les souscriptions qui doivent traverser plusieurs scènes, utilisez un script global (pas un script de scène).

Votre premier script complet

lua  ·  scripts/ennemi_simple.lua
-- Variables locales (persistent entre les frames)
local vie     = 30
local vitesse = 80
local portee  = 100

-- ─── Initialisation ──────────────────────────────────────────────
function init(entity)
    -- Les propriétés JSON de la scène sont dans `self`
    vie     = self.vie     or 30
    vitesse = self.vitesse or 80

    Anim.play(entity, "idle", true)
end

-- ─── Mise à jour chaque frame ────────────────────────────────────
function update(entity, dt)
    local joueur = World.findByTag("player")
    if not joueur then return end

    local distance = entity:getDistance(joueur)

    if distance < portee then
        Nav.moveTo(entity, joueur, vitesse)
        Anim.play(entity, "run", true)

        if distance < 30 then
            if Cooldown.use(entity.id, "attaque", 1.0) then
                joueur:sendMessage("takeDamage", { amount = 10 })
                Sound.play("data/sounds/hit.ogg")
            end
        end
    else
        Nav.stop(entity)
        Anim.play(entity, "idle", true)
    end
end

-- ─── Stat atteint zéro ───────────────────────────────────────────
-- `entity` est accessible ici comme global, pas besoin de paramètre
function OnStatZeroed(entityId, stat)
    if stat == "Vie" then
        Sound.play("data/sounds/mort.ogg")
        local pos = entity:getPosition()
        Particles.emit(pos.x, pos.y, { count = 20, speed = 150, lifetime = 0.6 })
        EntityState.disable(entity)
    end
end

-- ─── Réception de messages ───────────────────────────────────────
function OnMessage(msg, data)
    if msg == "takeDamage" then
        Stats.mod(entity.id, "Vie", -data.amount)
        Notify.floatingText(entity, "-" .. data.amount, { color = "red" })
    end
end

Les règles d'or

dt (delta time) — Multipliez toujours les vitesses par dt dans update. Sans ça, le jeu ira plus vite sur les PC rapides.
Variables locales — Déclarez avec local en dehors des fonctions pour qu'elles persistent entre les frames.
Vérifiez nil — World.findByTag() peut retourner nil. Vérifiez avant d'utiliser.
self = propriétés JSON — Les données de votre scène sont dans self.monChamp. Les valeurs par défaut se font avec self.champ or valeur_par_defaut.
Timer et Scheduler auto-scopés — Timer.after(1, fn) et Scheduler.start(fn) sans scope explicite sont automatiquement liés à Scene.current(). Impossible de créer accidentellement un timer qui fuit entre scènes.
Constantes de stats : Stat.Health — Le global Stat expose des constantes canoniques pour éviter les typos silencieuses. Préférez Stats.set(entity.id, Stat.Health, 100) à Stats.set(entity.id, "Healt", 100).
Erreurs script propagées via EventBus — Toute erreur (chargement, init, update) émet "script_error" : { entityId, path, error, phase }. Abonnez-vous pour afficher une console de debug en jeu : EventBus.on("script_error", function(d) Log.error(d.path .. " [" .. d.phase .. "] " .. d.error) end).
Hot-reload — Un script en erreur peut être rechargé à chaud sans redémarrer le jeu. ScriptRegistry.reload(entity.id) nettoie tous ses handlers, annule ses timers scopés et relance le chargement au prochain frame. ScriptRegistry.reloadAll() recharge tous les scripts en erreur d'un coup. Voir ScriptRegistry.
