ScriptRegistry

Appeler des fonctions dans d'autres scripts, envoyer des messages, et recharger des scripts à chaud pendant le développement.

Global automatique
Table interne : ScriptRegistry._envs stocke les environnements Lua de chaque entité (clé = entityId). Cette table est mise à jour automatiquement à chaque chargement et nettoyée à la destruction.

API — Inspection et appels

FonctionDescriptionRetour
ScriptRegistry.has(entityId)Vrai si l'entité a un environnement script actif.bool
ScriptRegistry.getEnv(entityId)Retourne l'environnement Lua de l'entité (table). Utile pour lire ses variables locales — à utiliser avec précaution.table | nil
ScriptRegistry.call(entityId, "fn", ...)Appelle la fonction fn dans le script d'une autre entité. Les arguments supplémentaires sont passés à la fonction. Silencieux si l'entité n'a pas de script ou si la fonction n'existe pas.any
ScriptRegistry.sendMessage(entityId, "msg", payload)Déclenche OnMessage(msg, payload) dans le script de l'entité cible via EventBus. Équivalent à entity:sendMessage().—

API — Hot-reload

Nettoyage complet : ScriptRegistry.reload() nettoie tous les handlers EventBus enregistrés (named handlers et EventBus.on() appelés dans init), annule les timers et coroutines scopés à l'entité, et remet le ScriptComponent à zéro. Le script sera rechargé intégralement au prochain frame.
FonctionDescriptionRetour
ScriptRegistry.reload(entityId)Recharge le script d'une entité. Nettoie les handlers, annule Timer/Scheduler scopés, réinitialise l'environnement. Le script sera re-exécuté (load + init) au prochain frame.bool
ScriptRegistry.reloadAll()Recharge tous les scripts actuellement en état d'erreur. Pratique pour relancer après avoir corrigé un bug. Retourne le nombre de scripts rechargés.int

Exemple — Communication inter-scripts

lua
-- Dans le script du gestionnaire de quête
local boss = World.findByTag("boss")

-- Appeler une fonction exposée dans le script du boss
local pv = ScriptRegistry.call(boss.id, "getPointsDeVie")

-- Activer le mode enragé du boss
ScriptRegistry.call(boss.id, "activerEnrage", 2.0)

-- Envoyer un message (déclenche OnMessage dans le script du boss)
ScriptRegistry.sendMessage(boss.id, "setPhase", { phase = 2 })

-- Vérifier que le boss a bien un script actif
if ScriptRegistry.has(boss.id) then
    Log.info("Boss prêt")
end

Exemple — Hot-reload en développement

lua  ·  Recharger un script après correction
-- Recharger le script d'une entité spécifique
local joueur = World.findByTag("player")
ScriptRegistry.reload(joueur.id)

-- Recharger tous les scripts en erreur d'un coup
local n = ScriptRegistry.reloadAll()
Log.info(n .. " script(s) rechargé(s)")
lua  ·  Console de développement (script global)
-- Script global de développement : rechargement automatique sur F5
function OnKeyDown(key)
    if key == "F5" then
        local n = ScriptRegistry.reloadAll()
        Notify.show("Hot-reload : " .. n .. " script(s)", { color = "cyan", duration = 2 })
    end
end

-- Surveiller les erreurs script en temps réel
EventBus.on("script_error", function(data)
    Log.error("[" .. data.phase .. "] " .. data.path .. " : " .. data.error)
    Notify.show("Erreur script : " .. data.path, { color = "red", duration = 4 })
end)

Exemple — Lire l'environnement d'une entité

Usage avancé : getEnv() expose directement l'environnement interne du script. Lire des valeurs est sûr, mais modifier des variables internes peut causer des comportements inattendus. Préférez call() ou sendMessage() pour interagir.
lua
-- Lire une variable locale du script d'une autre entité
local env = ScriptRegistry.getEnv(cible.id)
if env then
    local etat = env.etatCourant   -- variable locale du script cible
    Log.info("État du boss : " .. tostring(etat))
end
