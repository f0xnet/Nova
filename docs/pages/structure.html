Types de scripts

TypeSignatureDurée de vie
Script d'entitéinit(entity) + update(entity, dt)Tant que l'entité existe.
Script globalinit() + update(dt)Toute la durée du jeu (chargé via l'application).
Script de scèneinit() + update(dt)Uniquement quand la scène est active. Déchargé à chaque changement.

Le script de scène est déclaré dans le champ "script" du JSON de la scène. Tous les named handlers sont disponibles (OnTriggerEnter, OnKeyDown, etc.).

Script global (démarrage)

Le script global.lua est chargé une seule fois au lancement. C'est ici que vous définissez les raccourcis, les succès, les bindings.

lua  ·  data/scripts/global.lua
-- Contrôles
InputBind.register("bouger_gauche",  "Left")
InputBind.register("bouger_droite",  "Right")
InputBind.register("bouger_haut",    "Up")
InputBind.register("bouger_bas",     "Down")
InputBind.register("attaquer",       "Space")
InputBind.register("interagir",      "E")
InputBind.register("inventaire",     "I")

-- Langue
I18n.load("fr", "data/i18n/fr")
I18n.load("en", "data/i18n/en")
I18n.fallback("en")
local langue = Persist.get("langue", "fr")
I18n.set(langue)

-- Musique du menu
EventBus.on("scene_changed", function(data)
    if data.name == "menu_principal" then
        Sound.playMusic("data/music/menu.ogg")
    end
end)

Script de scène

Déclaré dans le JSON de la scène ("script": "data/scripts/monde1_scene.lua"), il est chargé automatiquement quand la scène devient active et déchargé au changement suivant.

lua  ·  data/scripts/monde1_scene.lua
function init()
    Sound.playMusic("data/music/monde1.ogg")
    Log.info("[monde1] scène active")
end

function update(dt)
    -- Logique propre à cette scène
end

function OnTriggerEnter(triggerId, entityId)
    if triggerId == "sortie_donjon" then
        Scene.transition("donjon_niveau1", { fade = true, duration = 0.5 })
    end
end

Script d'entité

Chaque script est attaché à une entité dans l'éditeur. Les fonctions de cycle de vie sont appelées automatiquement.

lua  ·  data/scripts/ennemi_gobelin.lua
-- Variables locales au script (privées à chaque entité)
local fsm
local joueur
local hp_max = 40

function init(entity)
    -- Initialiser les stats
    Stats.init(entity.id, { Vie = hp_max, VieMax = hp_max, Degats = 10 })

    -- Trouver le joueur
    joueur = World.findByTag("player")

    -- Créer la machine à états
    fsm = StateMachine.new("Patrouille")
    fsm:addState("Patrouille",
        function() Anim.play(entity, "walk", true) end,
        function(e, dt)
            if entity:getDistance(joueur) < 200 then
                fsm:transition("Poursuite")
            end
        end
    )
    fsm:addState("Poursuite",
        function() Anim.play(entity, "run", true) end,
        function(e, dt)
            if entity:getDistance(joueur) > 300 then
                fsm:transition("Patrouille")
            end
        end
    )
end

function update(entity, dt)
    fsm:update(entity, dt)
end

function OnStatZeroed(entityId, stat)
    if stat == "Vie" then
        local pos = entity:getPosition()
        Loot.dropFor(entity, "gobelin")
        Particles.emit(pos.x, pos.y, { count = 10, speed = 100, spread = 360 })
        EntityState.disable(entity)
    end
end

Bonnes pratiques

RèglePourquoi
Un script par type d'entitéPlus facile à maintenir et déboguer.
Variables locales en haut du scriptÉvite les conflits entre scripts.
Données dans data/ (JSON), logique dans scripts/Modifier les stats sans toucher au code.
Debug.enabled = false en productionÉvite les affichages de débogage chez le joueur.
Utiliser EventBus pour communiquer entre scriptsÉvite les dépendances directes entre entités.
Color.new(...), jamais Color(...)Le call direct passe par sol2 et peut échouer silencieusement dans les callbacks de rendu. Voir Math & Color.

Pièges à éviter

Color(r, g, b) direct. Utilise toujours Color.new(r, g, b). Le call direct existe (binding sol2) mais peut produire des couleurs invalides utilisées dans des callbacks de rendu, ce qui crashe sans message d'erreur visible. Tous les modules nova et exemples de cette doc utilisent Color.new.
Pour diagnostiquer. Toute erreur Lua est désormais propagée via l'événement script_error. Branche un listener au démarrage pour voir les erreurs en jeu : 
EventBus.on("script_error", function(d)
    Log.error(string.format("[%s] %s : %s", d.phase, d.path, d.error))
end)
