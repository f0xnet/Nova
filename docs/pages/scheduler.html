Scheduler

Écrire des séquences d'actions avec des pauses, comme si le code attendait — sans bloquer le jeu.

Global automatique
La différence avec Timer : Timer déclenche une action isolée après un délai. Scheduler permet d'enchaîner plusieurs actions avec des pauses entre elles, en écrivant le code de façon linéaire et lisible.
Nettoyage automatique : chaque coroutine est liée à une scène. Si aucun scope n'est fourni, Scene.current() est utilisé automatiquement. Au changement de scène, toutes les coroutines de la scène sortante sont annulées — une coroutine ne peut pas continuer à s'exécuter dans une nouvelle scène.

API

FonctionDescriptionRetour
Scheduler.start(fonction, scope, ...)Lance une séquence asynchrone. scope optionnel — défaut : Scene.current(). Les arguments supplémentaires sont passés à la fonction.coroutine
Scheduler.startWith(fonction, args, scope)Variante propre : args est une table {arg1, arg2, ...}. scope optionnel en 3e position — évite le nil obligatoire de start(fn, nil, arg1).coroutine
Scheduler.wait(secondes)Met la séquence en pause N secondes. À appeler uniquement à l'intérieur d'un Scheduler.start().—
Scheduler.cancelScope(scope)Annule toutes les coroutines d'un scope donné.—
Scheduler.clear()Annule toutes les coroutines en cours (reset global).—

Exemple — Séquence d'intro d'un boss

lua
-- Séquence cinématique : texte, pause, déplacement caméra, combat
Scheduler.start(function()
    -- Étape 1 : afficher un message
    Notify.show("Un bruit sourd résonne...", { duration = 2 })
    Scheduler.wait(2.0)   -- attendre que le message soit lu

    -- Étape 2 : déplacer la caméra vers le boss
    local boss = World.findByTag("boss")
    Camera.unfollow()
    Camera.moveTo(boss:getPosition().x, boss:getPosition().y, 2.0, "easeInOut")
    Scheduler.wait(2.5)

    -- Étape 3 : zoom + message dramatique
    Camera.zoomTo(1.5, 0.5, "easeOut")
    Notify.show("GARDIEN DES PROFONDEURS", { color = "red", size = 1.5, duration = 3 })
    Sound.play("data/sounds/boss_roar.ogg")
    Camera.shake(0.8, 10)
    Scheduler.wait(2.0)

    -- Étape 4 : retour au joueur, début du combat
    Camera.follow(World.findByTag("player"))
    Camera.zoomTo(1.0, 1.0, "easeOut")
    Scheduler.wait(0.5)
    EventBus.emit("boss_combat_commence", {})
end)

startWith — passer des arguments sans ambiguïté

lua
-- Problème avec start() : pour passer des args sans scope, il faut un nil explicite
Scheduler.start(deplacerVersPoint, nil, 400, 250, 80)

-- Solution : startWith() — args en table, scope optionnel en 3e position
Scheduler.startWith(deplacerVersPoint, {400, 250, 80})

-- Avec scope explicite (ex : lié à l'entité, pas à la scène)
Scheduler.startWith(patrouille, {entity, waypoints}, tostring(entity.id))

-- Exemple de fonction coroutine avec args
local function deplacerVersPoint(x, y, vitesse)
    Nav.moveTo(entity, {x=x, y=y}, vitesse)
    Scheduler.wait(2.0)
    Nav.stop(entity)
end

Exemple — Dialogue séquentiel

lua
-- Faire parler un PNJ ligne par ligne
Scheduler.start(function()
    Notify.show("PNJ : Bienvenue, voyageur.")
    Scheduler.wait(2.5)

    Notify.show("PNJ : Le donjon à l'est est dangereux...")
    Scheduler.wait(2.5)

    Notify.show("PNJ : Prenez cette potion. Vous en aurez besoin.")
    Scheduler.wait(2.0)

    Inventory.add(joueur.id, "potion_vie", 1)
    Notify.show("Reçu : 1 Potion de vie", { color = "green" })
end)
